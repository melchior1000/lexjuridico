# LEX — análise reversa de 14/09/2026

Este documento registra o estado técnico verificado no repositório. Ele não substitui homologação visual ou de provedores externos.

## Interface comercial

- Login em light DOM com tokens `--login-*`, cascade layers e classes próprias.
- O bloco temporário CUT 4 e as cores temáticas inline do login foram retirados.
- `login-theme.js` não remove mais regras nem propriedades da cascata; apenas marca a preparação do tema.
- Home, Processos, Prazos, Escritório, LEX e Mais permanecem na casca comercial.
- Voz usa Web Speech API quando disponível.
- Abas de Processos/Prazos e fila de Tarefas estão ligadas a funções reais da interface.

## Chat do LEX

O chat comercial passa a manter histórico curto em `sessionStorage`, separado entre conversa geral e cada `processo_id`, e envia esse histórico ao endpoint `/api/vivo/conversar`. A troca de processo troca também o fio de conversa.

Quando um `processo_id` fornecido não existe na carteira do servidor, a entrada HTTP recusa o contexto em vez de cair silenciosamente para conversa geral. Isso impede uma análise aparentemente processual sem o processo correto.

## Agentes e tarefas

Os playbooks por tipo/setor e o TaskEngine continuam sendo a fonte de treinamento/alocação. O fluxo comprovado é tarefa -> agente -> entrega/pendência -> revisão. A existência de playbooks não prova uma malha de conversa livre entre agentes.

## Shadow DOM, Web Components e Lit

Não fazem parte do runtime atual. Não são usados como correção do login. O critério de adoção está em `docs/FRONTEND_COMPONENT_BOUNDARIES.md`: só entram quando um recurso completo migrar com markup, eventos, estado e contrato de integração.

## Validação

A suíte deve passar por `npm run check` e `npm test` no CI antes do merge. O resultado do CI é evidência de regressão automatizada, não de homologação de produção.

## Produção

Git e Vercel são estados separados. Um commit verde na `main` não é tratado como publicado até o deployment correspondente ser confirmado. Se o status da Vercel estiver limitado por quota/rate limit, produção pode continuar servindo um commit anterior.

## Pendências que exigem prova externa

- WhatsApp: testes automatizados não substituem sessão real pareada + mensagem de entrada/saída no aparelho.
- Telegram: testes automatizados não substituem mensagem real confirmada pelo provedor.
- PJe/DataJud: rotas e testes não equivalem a homologação ponta a ponta em tribunal.
- Vercel: o conector precisa enxergar o projeto/time correto para auditar deployment, build e variáveis diretamente.
- Interface: CI não substitui inspeção visual em celular, tablet e desktop.
